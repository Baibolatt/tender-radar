# SMC/ICT Research Bot

Исследовательский проект по концепциям **SMC/ICT** на Python: загрузка свечей,
разметка сигналов на графике и событийный бэктест стратегии.

> **Только исследование.** Реальные ордера не выставляются, API-ключи не нужны.
> Проект не является торговым советником и не гарантирует прибыль.

Стек: `pandas`, `numpy`, `ccxt`, `smartmoneyconcepts`, `vectorbt`, `matplotlib`.

---

## Быстрый старт

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 1. скачать/обновить BTC/USDT 15m (кэш в data/cache/)
python main.py fetch --days 180

# 2. разметка на графике (последние 400 свечей)
python main.py markup --last 400

# 3. сигналы и сделки
python main.py signals
python main.py backtest

# 4. всё сразу + график с входами/SL/TP
python main.py all --last 400

# 5. сверка детекторов с библиотекой smartmoneyconcepts
python main.py validate
```

Графики складываются в `charts/`, CSV-отчёты (`--save`) — в `reports/`,
свечи — в `data/cache/`. Все времена в UTC.

Полезные флаги: `--symbol`, `--timeframe`, `--htf`, `--days`, `--swing`,
`--rr`, `--refresh`, `--no-bias-filter`, `--theme light|dark`,
`--start/--end` (окно графика), `--entry edge|mid`.

## Как гарантируется отсутствие lookahead bias

Ключевая идея: у каждого события есть **два индекса**.

| Поле | Смысл |
|---|---|
| `index` / `time` | где событие *находится* (нужно для рисования) |
| `confirm_index` / `confirm_time` | когда о нём *можно узнать* (только это видят стратегия и бэктест) |

Правила подтверждения:

| Событие | Подтверждается |
|---|---|
| Свинг | через `swing_length` (по умолчанию 3) закрытых свечей справа: `confirm = index + n` |
| FVG | на баре после средней свечи: `confirm = middle + 1` |
| BOS / CHoCH | на закрытии бара, пробившего уровень |
| Свип | на закрытии бара, который проколол уровень и вернулся за него |
| HTF-байас | по *закрытию* HTF-свечи; значение применяется только следующим LTF-барам |

Событие, подтверждённое на закрытии бара `t`, становится доступным для входа
на баре `t+1` и позже. Вход никогда не оценивается на баре, породившем
триггер. Свинг-индикаторы, которые «смотрят в будущее» (например,
`smartmoneyconcepts`), используются **только** для сверки в `validate`, но не
как источник сигналов.

Проверка: `tests/test_lookahead.py` считает все детекторы и стратегию на
полном ряду и на усечённом. Всё, что подтвердилось до точки отсечения, обязано
совпасть бит-в-бит.

```bash
python -m unittest discover -s tests -v
```

## Детекторы

- **Свинги** — локальные экстремумы окна `[i-n, i+n]`; схлопывание плато, чтобы
  равные экстремумы не давали серию пивотов.
- **BOS / CHoCH** — пробой закрытием последнего непробитого подтверждённого
  свинга. CHoCH — пробой против текущей структуры, BOS — по направлению.
- **FVG** — три свечи: гэп между `high[i-1]` и `low[i+1]` (бычий) или
  `low[i-1]` и `high[i+1]` (медвежий). Отслеживается частичное/полное
  перекрытие, но только как разметка — стратегия использует геометрию гэпа.
- **Order Block** — последняя свеча противоположного цвета перед пробоем
  структуры.
- **Свип ликвидности** — прокол уровня свинга с возвратом на ту же свечу;
  требуется буфер `sweep_min_atr * ATR`, чтобы отсеять шум. Уровень
  «расходуется» при любом проколе.

`python main.py validate` сравнивает свинги и FVG с `smartmoneyconcepts`
(на референсном прогоне: свинги ~84 % recall — расхождения на плато и краевых
пивотах; FVG 704/704).

## Правила стратегии

Длинная сделка (короткая — зеркально):

1. **HTF-байас** бычий (`structure` — последняя подтверждённая структура HTF,
   либо `ema`).
2. **Свип** подтверждённого свинг-лоу: фитиль ниже уровня, закрытие выше.
3. **CHoCH** вверх в течение `max_bars_after_sweep` (по умолчанию 40) баров
   после свипа.
4. **Возврат в FVG**, сформированный после свипа, в течение
   `max_bars_after_choch` (20) баров. Гэп должен целиком лежать выше стопа.
5. **Вход** лимитом по краю FVG (`edge`) или середине (`mid`). Лимит обязан
   стоять ниже открытия бара — иначе это не ретест, а рыночный вход.
6. **SL** — за экстремум свипа минус `sl_buffer_atr * ATR`; **TP** = `rr`
   (по умолчанию 2.0) от риска.

Сетап отменяется, если истекло окно, цена закрылась за экстремумом свипа,
HTF-байас развернулся или появился противоположный CHoCH.

## Модель исполнения и допущения

- Одна позиция одновременно; вход не совершается на баре выхода.
- Размер позиции: риск `risk_per_trade` (1 %) от текущего капитала, но не
  более `max_position_pct` (95 %) капитала.
- На баре входа проверяется **только стоп**: благоприятный ход мог случиться
  до заполнения лимита, поэтому TP на этом баре не засчитывается.
- Если SL и TP оба внутри одного бара — срабатывает **SL**
  (`pessimistic_intrabar`).
- Выход в конце данных — по последнему закрытию (`eod`).
- Комиссии и проскальзывание: `fees` 0.04 % и `slippage` 0.02 % на сторону,
  учитываются через `vectorbt.Portfolio.from_orders`.
- Сделка, закрытая на баре входа, переносится в учёте на следующий бар по той
  же цене стопа — иначе vectorbt неттит ордера с одинаковым временем. PnL не
  меняется, флаг `same_bar_exit` сохраняется в отчёте.

Это базовый бэктест, а не оптимизированная система: параметры не подбирались
на тестовом периоде, walk-forward не выполнялся.

## График

`main.py markup` рисует три панели: цену (свечи, свинги, BOS/CHoCH, FVG,
Order Blocks, свипы), объём и HTF-байас. `--trades` добавляет вход, SL, TP и
зоны риска/прибыли; `--theme dark` — тёмную тему.

Направление свечей кодируется дважды: цветом **и** формой (бычьи залиты,
медвежьи полые) — так график остаётся читаемым при дальтонизме. Палитра
светлая/тёмная взята из проверенного набора и рассчитана на контраст.

## Основные параметры (`config.py`)

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `timeframe` / `htf_timeframe` | `15m` / `1h` | LTF и HTF |
| `swing_length` | 3 | лаг подтверждения свинга (свечей справа) |
| `htf_bias_mode` | `structure` | `structure` или `ema` |
| `sweep_min_atr` | 0.05 | минимальный прокол в долях ATR |
| `rr` | 2.0 | тейк = RR × риск |
| `max_bars_after_sweep` | 40 | окно для CHoCH |
| `max_bars_after_choch` | 20 | окно для входа в FVG |
| `sl_buffer_atr` | 0.25 | запас стопа за свипом |
| `entry_at` | `edge` | `edge` или `mid` FVG |
| `risk_per_trade` | 0.01 | риск на сделку |
| `fees` / `slippage` | 0.0004 / 0.0002 | издержки на сторону |
| `pessimistic_intrabar` | `True` | SL раньше TP внутри бара |

## Ограничения

- Нет реальной торговли, стриминга и управления позициями вживую.
- Нет walk-forward / оптимизации параметров — результаты зависят от периода.
- Исполнение моделируется по OHLC; внутрибаровая последовательность неизвестна
  и трактуется консервативно.
- `smartmoneyconcepts` ретроспективен; он не используется для принятия решений.
- funding, задержки API, частичные исполнения и проскальзывание сверх
  заданного не моделируются.
